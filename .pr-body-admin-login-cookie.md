## Problem

Admins cannot log in to production. The /api/auth/admin-login route authenticates the user successfully and creates a `sessions` row, but the browser never receives the `__Secure-amph_session` cookie, so `src/proxy.ts:120` bounces them straight back to `/admin-login`. No error message, just a redirect loop.

## Root cause

`performLogin()` in `src/app/actions/login.action.ts:142` calls `deps.plantCookie(...)`, which is `setAuthCookie` from `src/lib/auth.ts`. With no `target` argument, `setAuthCookie` writes to the implicit `cookies()` store (the request's implicit response).

The admin-login route then returns a fresh `NextResponse.redirect()`. A fresh `NextResponse` does NOT inherit cookies from the implicit store. So the cookie is set on a response object that is immediately discarded, and the browser never sees the Set-Cookie header.

The same bug was fixed in `/api/auth/login/route.ts:67-75` and `/api/auth/signup/route.ts:61-69` by PR #182 ("plant session cookie on the redirect response"), but `/api/auth/admin-login/route.ts` was added later in PR #174 and never received the patch.

## Fix

Mirror the pattern from `/api/auth/login` and `/api/auth/signup`:

1. Build the `NextResponse.redirect('/admin', 303)` first.
2. Call `setAuthCookie(token, expiresAt, response.cookies, { isHttps })` to plant the cookie on that response so the browser receives it with the 303.
3. Use `new URL(request.url).protocol === 'https:'` as the single source of truth for the cookie name (`__Secure-amph_session` in prod) AND the Secure flag.

Also pins the `not_admin` branch: a non-admin user who authenticates must NOT receive a session cookie (no half-authenticated state where they have a session but cannot reach `/admin`).

## Rollout note

After merge and Vercel deploy, admins may need to clear the existing `amph_session` cookie from their browser, or hard-reload. The proxy will accept their session as soon as the new cookie arrives. No DB cleanup needed (the `sessions` rows created during the outage are still valid; the cookie just wasn't reaching the browser).
