# Module 7 Decision Cheat Sheet — Bids & Budgets

## One-line objective

Set budget and bid logic, diagnose pacing, and make controlled bid changes.

> **Non-negotiable:** Change one variable, define the guardrail, and write the review date before you click save.

## Fast decision sequence

1. **Observe:** identify the signal and its source.
2. **Diagnose:** explain the most plausible leak or opportunity.
3. **Choose:** take the smallest safe action.
4. **Control:** name the guardrail and owner.
5. **Review:** set a date or evidence threshold.

## Signals at a glance

| Signal                            | Use it to             |
| --------------------------------- | --------------------- |
| Bid versus target ACOS            | Observe before acting |
| Budget exhaustion timing          | Observe before acting |
| Clicks and orders after a change  | Observe before acting |
| Evidence volume and review window | Observe before acting |

## Safe action standard

Raise only when incremental traffic is relevant and economics support it; lower or hold when the evidence does not.

## Ask before saving a change

| Question                                  | If the answer is “no”                         |
| ----------------------------------------- | --------------------------------------------- |
| Can I point to evidence?                  | Watch, research, or request the missing data. |
| Is the action within my permission level? | Notify or escalate.                           |
| Does it change only one variable?         | Split the actions into separate tests.        |
| Is there a guardrail and review date?     | Do not execute yet.                           |

## Core vocabulary

| Term     | Meaning                                                           |
| -------- | ----------------------------------------------------------------- |
| Bid      | Maximum willingness to compete for an eligible click opportunity. |
| Budget   | Spend capacity over a defined time period.                        |
| Pacing   | How budget is consumed across the day or period.                  |
| Baseline | The measured condition before a controlled change.                |
