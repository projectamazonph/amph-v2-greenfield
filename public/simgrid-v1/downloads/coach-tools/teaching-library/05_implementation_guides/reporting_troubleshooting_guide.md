# Reporting and Troubleshooting Guide

## Purpose

Use this guide in Module 10 to write reports that produce a decision rather than a dashboard recital.

## Narrative formula

**Result → Driver → Action → Guardrail → Checkpoint**

Every claim needs evidence. When conversion or revenue is weak, troubleshoot in this order: **stock → price → reviews → competitors → PPC**. This order prevents the team from using PPC levers to hide an offer problem.

## Quality test

| Weak report              | Decision-ready report                                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| “ACOS went down.”        | “ACOS moved from X to Y after [single action]; [driver] is supported by [evidence]. We will protect [guardrail] and review on [date].” |
| “We optimized keywords.” | “We moved [term] to Exact, negated [term], and left [term] on watch because evidence was insufficient.”                                |
