# Module 9 Field Handout — Weekly Optimization

## The job

By the end of this module, you should be able to **Run a weekly cadence, change one variable at a time, and use data thresholds.** The required practice handoff is **Account Audit + Search Term Triage** (`account-audit.html / search-triage.html`), with a target of **75% each / 70% quiz**.

> **Operating rule:** Observe, diagnose, hypothesize, change one variable, log, then review.

## What to look for

- **1.** Weekly baseline and delta
- **2.** Single variable changed
- **3.** Evidence threshold used
- **4.** Result, learning, and next action

## Worked thinking

Weekly operations are not a list of random optimizations. A change log must prove what changed, why, and what happened afterward.

## Practice before you open the simulator

Design a weekly operating sheet for one account: Monday data review, diagnosis, hypothesis, controlled change, documentation, and Friday check.

## Decision standard

Do not stack multiple changes against the same problem when you need to know what caused the outcome.

## Key language

| Term       | Plain-language meaning                                    |
| ---------- | --------------------------------------------------------- |
| Hypothesis | A testable explanation for observed performance.          |
| Variable   | The one condition intentionally changed in an experiment. |
| Threshold  | The evidence rule that allows a decision.                 |
| Cadence    | The recurring operating rhythm for review and action.     |

## Exit ticket

Write one sentence for each prompt before moving on: What is the observed evidence? What is your smallest safe action? What guardrail or review date will tell you whether the action worked?
