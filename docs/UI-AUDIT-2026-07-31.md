# UI Audit — AMPH Academy v2

**Auditor:** Omnibot Design Agent  
**Date:** 2026-07-31  
**Stack:** Next.js 16, React 19, CSS Modules, @astryxdesign/core, Phosphor Icons  
**Design System:** "The Field Manual" — warm paper neutrals, Waybill Orange accent, dense utilitarian layout  
**Skills loaded:** impeccable, ui-ux-pro-max, web-design-guidelines

---

## Executive Summary

The AMPH Academy v2 codebase has a **solid architectural foundation** — clean token system, disciplined color palette, well-structured component hierarchy, and thoughtful accessibility patterns (focus rings, aria labels, semantic HTML). However, the execution reads as **early functional prototype** rather than **polished product**. The "Field Manual" aesthetic is articulated well in theory (DESIGN.md) but not yet fully realized in practice. The most critical gap: **the sidebar and overall experience feel inert** — there's almost no micro-interaction, no smart navigation, no visual hierarchy differentiation between sections, and very little that rewards the admin for spending time in the tool.

This audit covers **27 pages/components** across the public site, admin panel, and shared UI layer.

## 🔴 Critical Issues (Must Fix)

### C-01: Sidebar Is a Flat, Unsectioned List
**File:** `src/components/admin/NavSidebar.tsx` + `.module.css`  
**Impact:** 12 nav items stacked in a single flat list with zero visual grouping. No sections, no separators, no category labels.

**Current state:** All 12 items (Dashboard, Users, Courses, Content, Payments, Refunds, Live Classes, Simulators, Badges, Quizzes, Certificates, Settings) are rendered identically with `gap: 2px`. There's no way to visually distinguish "content management" from "operations" from "settings".

**Fix — Smart Navigation Groups:**
```
┌─ OVERVIEW ─────────────────┐
│ ◼ Dashboard                │
├─ CONTENT ──────────────────│
│ ◻ Courses                  │
│ ◻ Content                  │
│ ◻ Quizzes                  │
│ ◻ Simulators               │
│ ◻ Badges                   │
├─ OPERATIONS ───────────────│
│ ◻ Users                    │
│ ◻ Payments                 │
│ ◻ Refunds                  │
│ ◻ Live Classes             │
│ ◻ Certificates             │
├────────────────────────────│
│ ◻ Settings                 │
└────────────────────────────┘
```
- Add section labels using `font-family: var(--font-mono)` at 10px, uppercase, ink-500
- Add `border-top: 1px solid var(--border)` between groups
- Add a "quick search" input at top of nav (Cmd+K style) for admins with lots of sections
- Add badge counts on key items (e.g., Pending Refunds: 3, New Users: 12)

### C-02: No Hover/Focus Lift on Sidebar Items
**File:** `NavSidebar.module.css`  
**Current:** `.item:hover` only changes `background` and `color`. No spatial feedback (no translate, no shadow).

**Fix:** Add `transform: translateX(2px)` on hover for sidebar items to give physical depth. The design spec says "borders as elevation, shadows only on interaction" — the sidebar items should earn their shadow on hover:
```css
.item:hover {
  background: var(--surface-2);
  color: var(--ink-900);
  transform: translateX(2px);
  box-shadow: var(--shadow-sm);
}
```

### C-03: Cards Across the App Lack Consistent Lift
**Files:** Multiple `page.module.css` files  
**Issue:** The `.astryx-card` override in `globals.css` adds `box-shadow: var(--shadow-sm)` globally, but many cards defined in CSS modules use raw `border: 1px solid var(--border)` without shadow, creating inconsistent depth.

**Affected pages:**
- `/courses` cards — shadow ✓, but no hover lift
- `/dashboard` in-progress cards — shadow on hover only, flat at rest
- `/tools` cards — shadow ✓
- `/pricing` cards — shadow on highlighted only
- Admin filter bars — no card wrapper, float as raw flex rows
- `/profile` sections — shadow ✓

**Fix:** Establish a consistent card elevation system:
```css
/* At rest: border only (Field Manual flat) */
.card { border: 1px solid var(--border); }
/* On hover: border + shadow = "lifted" */
.card:hover { box-shadow: var(--shadow-sm); transform: translateY(-1px); }
```

### C-04: Dashboard Empty States Are Static Dead Zones
**File:** `src/app/admin/page.tsx`  
**Issue:** The "Recent activity" and "Pending actions" sections render empty states with Phosphor icons. These are well-designed visually but **completely inert** — no skeleton loaders, no animation, no way to trigger content. For a fresh deployment, the entire bottom half of the dashboard is a dead zone.

**Fix:**
- Add a subtle shimmer/pulse animation to the empty state icon (CSS `@keyframes pulse`)
- Add a "Generate sample data" or "View audit log" CTA button in the empty state
- Consider skeleton card placeholders that resolve to empty state after 1s

## 🟠 High-Priority Enhancements

### H-01: No Breadcrumb Trail on Admin Sub-Pages
**Files:** `src/components/admin/TopBar.tsx`, all admin sub-pages  
**Issue:** The TopBar component has a `breadcrumb` prop, but only the dashboard page uses it (with a simple "Admin" label). All sub-pages (`/admin/users`, `/admin/courses`, `/admin/payments`, etc.) render without breadcrumbs.

**Fix:** Every admin sub-page should render breadcrumbs:
```
Admin ▸ Users ▸ John Doe
Admin ▸ Courses ▸ [Course Name] ▸ Modules
Admin ▸ Payments
```
Update the breadcrumb prop in each page.tsx to include the full path.

### H-02: Tables Lack Row Hover and Zebra Striping
**Files:** `AdminUsersTable`, `AdminCoursesTable`, `AdminPaymentsTable`, `AdminRefundsTable`, `AdminAuditLogTable`, `AdminBadgesTable`, `AdminDiscountCodesTable`, `AdminLiveClassesTable`, `AdminSimulatorsTable`  
**Issue:** All admin tables use `border-bottom: 1px solid var(--border)` for row separation but have no hover state on rows and no alternating backgrounds. Dense tables without visual rhythm cause eye strain.

**Fix:**
```css
.tr:hover {
  background: var(--surface-2);
}
/* OR zebra striping: */
.tr:nth-child(even) {
  background: var(--surface-2);
}
```

### H-03: No Loading States Anywhere
**Issue:** None of the pages show loading indicators. Next.js App Router supports `loading.tsx` files for instant loading UI, but none exist in the project.

**Fix:** Add `loading.tsx` to key routes:
- `/admin` — skeleton stat tiles + skeleton cards
- `/admin/users` — skeleton table rows
- `/admin/courses` — skeleton table rows
- `/courses` — skeleton course cards
- `/dashboard` — skeleton enrollment cards
- `/pricing` — skeleton pricing cards

### H-04: Filter Bars Are Visually Disconnected from Tables
**Files:** `/admin/users/page.module.css`, `/admin/courses/page.module.css`, `/admin/payments/page.module.css`  
**Issue:** Filter controls (search input + select dropdowns + Apply button) are rendered as bare flex rows above the table card. They float in whitespace with no visual container, making them look like an afterthought.

**Fix:** Wrap filters in a subtle card or surface:
```css
.filters {
  background: var(--surface-1);
  border: 1px solid var(--border);
  border-radius: var(--radius-md);
  padding: var(--space-4);
  margin-bottom: var(--space-4);
}
```

### H-05: Pricing Cards Lack Visual Differentiation
**File:** `src/app/pricing/page.module.css`  
**Issue:** The highlighted "mastery" tier gets an accent border and glow shadow, but the two non-highlighted tiers look identical and bland. The `.features`, `.blurb`, and `.plus` CSS classes exist but are unused — the cards only show name, price, and CTA.

**Fix:** Implement feature lists inside pricing cards to justify the price difference. Use the already-defined CSS classes.

### H-06: Student Dashboard Has No Sidebar Navigation
**File:** `src/app/dashboard/page.tsx`  
**Issue:** The student dashboard is a standalone page with no navigation context. There's no sidebar, no header nav, no way to get to `/tools`, `/courses`, `/profile` without using the URL bar. The "Sign out" link is buried at the bottom.

**Fix:** Add a student-facing header/nav bar with links to Dashboard, Courses, Tools, Profile, and Sign Out. Consider a minimal top bar (not a full sidebar) that stays consistent across all student-facing pages.

## 🟡 Medium-Priority Defects

### M-01: Login/Signup Forms Are Centered Without Context
**Files:** `src/app/login/LoginForm.tsx`, `src/app/signup/SignupForm.tsx`  
**Issue:** Both forms are vertically and horizontally centered with no surrounding context — no branding, no value proposition, no visual anchor. The "AMPH" logo text uses `font-family: var(--font-mono)` at 20px, which reads as a code label, not a brand.

**Fix:** Add a subtle background illustration or texture (consistent with the "Field Manual" aesthetic). Add a one-liner value prop below the logo. Use `--font-display` for the brand name, not mono.

### M-02: No Transition on Page Navigation
**Issue:** Next.js App Router client-side navigation has no transition. Pages snap instantly. The design spec limits motion to "fade, slide-up, color transition" but none are implemented.

**Fix:** Add a subtle `opacity` + `translateY` entrance animation to the main content area:
```css
.main > * {
  animation: fadeSlideUp var(--duration-base) var(--ease-out);
}
@keyframes fadeSlideUp {
  from { opacity: 0; transform: translateY(8px); }
  to { opacity: 1; transform: translateY(0); }
}
```

### M-03: Course Cards Have No Hover Feedback
**File:** `src/app/courses/page.module.css`  
**Issue:** `.card:hover` adds `border-color: var(--accent)` and `box-shadow` — but there's no spatial movement. The card stays flat. For a training platform, course cards should feel clickable.

**Fix:** Add `transform: translateY(-2px)` on hover.

### M-04: Dashboard Progress Bars Are Too Thin
**File:** `src/app/dashboard/page.module.css`  
**Issue:** Progress bars are `height: 6px` — barely visible. On a dense page, they get lost.

**Fix:** Increase to `height: 8px` and add a subtle `border-radius` for a pill shape.

### M-05: Profile Page Lacks Visual Hierarchy
**File:** `src/app/profile/page.tsx`  
**Issue:** The profile page shows two sections (Profile info + Badges) in a 2-column grid. The sections use identical styling — no visual weight difference. The "Profile" section should be primary and "Badges" secondary.

### M-06: Tools Page Cards Are Identical — No Status Indicator
**File:** `src/app/tools/page.tsx`  
**Issue:** All 5 tool cards look the same. There's no indication of which tools the user has attempted, their scores, or completion status. A returning user has to click into each tool to find their progress.

**Fix:** Add a status dot or mini score badge to each tool card.

### M-07: Certificate Page Has No Print Styles
**File:** `src/app/certificates/[hash]/page.tsx`  
**Issue:** The certificate page exists but has no `@media print` styles. Users who want to print their certificate get the full page chrome.

### M-08: Mobile Sidebar Becomes Horizontal Scroll — No Visual Cue
**File:** `NavSidebar.module.css`  
**Issue:** Below 1023px, the sidebar becomes a horizontal scrollable nav. But there's no visual indicator that the nav is scrollable (no fade gradient, no scroll hint). Users may not discover items beyond the visible area.

**Fix:** Add a CSS gradient fade on the right edge:
```css
@media (max-width: 1023px) {
  .nav {
    mask-image: linear-gradient(to right, black 85%, transparent 100%);
  }
}
```

## 🔵 Low-Priority Enhancements (Polish)

### L-01: Stat Tiles on Dashboard Could Show Trend Indicators
The 6 KPI tiles show flat numbers. Adding a small ↑↓ arrow with percentage change vs. last period would make the dashboard actionable.

### L-02: Empty States Across the App Are Inconsistent
- Dashboard empty states: accent icon circle + title + body ✓
- Courses empty state: plain text
- Dashboard "no enrollments" empty state: dashed border wireframe
- Profile "no badges": plain muted text

**Fix:** Standardize on the dashboard empty state pattern (icon + title + body) everywhere.

### L-03: No Keyboard Shortcut for Common Admin Actions
Admin power users would benefit from keyboard shortcuts (Cmd+K for search, N for new course, etc.). The sidebar already has `focus-visible` rings — extend to global shortcuts.

### L-04: Orphaned CSS Classes in Pricing
**File:** `src/app/pricing/page.module.css`  
The `.blurb`, `.features`, `.feature`, and `.plus` classes are defined but never used. Either implement them or remove them.

### L-05: No Dark Mode Toggle Despite Token System
**File:** `globals.css`  
The `[data-theme="dark"]` selector exists with complete token overrides, but there's no UI to toggle it. The dark theme is fully tokenized and ready — just needs a toggle switch in settings.

### L-06: Brand Mark in Sidebar Is Very Small
**File:** `NavSidebar.module.css`  
The 2×2 accent square grid is only 14px (6px squares + 2px gap). It's barely visible and doesn't register as a brand mark. Consider scaling to 20px or adding the AMPH wordmark more prominently.

### L-07: No Toast/Notification System
**Issue:** Actions like "Course created", "User updated", "Refund processed" have no visual feedback. The user performs an action and has to manually verify it worked.

**Fix:** Implement a toast notification system using the `--z-toast` token that's already defined.

### L-08: Sidebar Footer UserCard Has No Click Target for Profile
**File:** `src/components/admin/UserCard.tsx`  
The UserCard shows avatar + name + role but clicking the card does nothing. Only the logout button is interactive.

**Fix:** Make the UserCard clickable to navigate to `/admin/settings` or a profile page.

## 🎨 Sidebar Smart Navigation — Detailed Proposal

The sidebar is the **single most impactful UI improvement** you can make. Here's a comprehensive redesign:

### 1. Add Section Grouping
Group the 12 items into 4 logical sections with monospace labels:
- **OVERVIEW** — Dashboard
- **CONTENT** — Courses, Content, Quizzes, Simulators, Badges
- **OPERATIONS** — Users, Payments, Refunds, Live Classes, Certificates
- **SYSTEM** — Settings

### 2. Add Badge Counts
Show pending-item counts on key nav items:
- Users: total count
- Payments: today's count
- Refunds: pending count (highlighted in danger)
- Certificates: pending revocations

### 3. Add Quick Search
A collapsible search input at the top of the sidebar (or a Cmd+K overlay) that filters nav items and recent pages.

### 4. Add Collapsible Sections
Allow sections to collapse/expand. Persist state in localStorage.

### 5. Add Recent Pages
Below the main nav, show "Recently visited" with the last 3 admin pages for quick return navigation.

### 6. Add Active Page Context
When on a detail page (e.g., `/admin/courses/abc123`), highlight the parent item AND show a sub-item indicator (e.g., "Course: Introduction to PPC").

### 7. Add Keyboard Navigation
Arrow keys to move between items, Enter to select, Escape to close search.
