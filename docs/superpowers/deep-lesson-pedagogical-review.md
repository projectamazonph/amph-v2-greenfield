# Deep Multi-Block Lesson Pedagogical Review

## Executive judgment

The eight deep lessons are **instructionally credible but not uniformly optimized**. The visuals are generally aligned with the lesson decisions and use evidence rather than decoration. The main weakness is not missing content; it is **sequencing discipline**. Several lessons place multiple completed visuals together immediately before the learner attempt, which creates a visual dashboard rather than a progressive explanation. The strongest lessons make the learner move from signal to calculation to decision. The weaker deep lessons show the framework correctly but reveal too much of the answer before the learner has to choose.

The review uses a 12-point rubric covering sequence alignment, cognitive load, evidence use, active attempt, practice handoff, and feedback quality. Scores are judgments about instructional design, not automated component counts.

| Lesson | Score | Judgment | Primary issue |
| --- | ---: | --- | --- |
| 1.1 | 8/12 | Revise | Too many overlapping diagnostic visuals; generic and dedicated flows repeat the same reasoning. |
| 1.2 | 10/12 | Strong with minor revision | Good formula-to-diagnosis sequence; move the learner choice earlier and make feedback more diagnostic. |
| 2.1 | 9/12 | Usable but revise | Comparison, hierarchy, and routing are clustered and abstract rather than driven by one concrete keyword. |
| 2.3 | 10/12 | Strong with minor revision | Excellent scope and maintenance logic; the completed boards reveal the answer before classification. |
| 4.4 | 11/12 | Strong | Best simulator handoff; protect the challenge by separating pre-flight criteria from post-attempt feedback. |
| 6.1 | 10/12 | Strong with minor revision | Good risk framing; strategy selection should happen before the full decision flow is revealed. |
| 7.1 | 9/12 | Usable but revise | Strong operating cadence, but the five-category board needs a worked term and a deliberate learner routing step. |
| 8.3 | 10/12 | Strong with minor revision | Good evidence-to-action chain; gap scoring and competitor labels need more observable criteria. |

## Lesson-specific findings

### Lesson 1.1 — Read PPC Data Before You Change PPC Data

The lesson has the richest visual system, and the core sequence is correct: metric roles, a concrete coffee-grinder case, ordered diagnosis, pattern recognition, practice, then client recommendation. The problem is **redundancy**. The generic `decision-sequence`, `pattern-board`, and `practice-workbench` sit beside the dedicated `read-before-change-flow`, while the original `diagnostic-map` and `Big Six` visuals already establish the same journey. Eight blocks create a high-density lesson in which the learner may spend more effort navigating representations than reasoning about the case.[1]

The highest-value revision is to make one canonical path. Keep the Big Six matrix, coffee-grinder case, one decision flow, one practice workbench, and the recommendation builder. Fold the generic decision tree and pattern board into the dedicated flow or remove them. The practice workbench should begin with a blank diagnosis and reveal the coach path only after the learner selects the first lever. The final recommendation builder should explicitly reuse the learner’s selected evidence, not ask for a new summary from scratch.

**Recommended score after revision: 10–11/12.**

### Lesson 1.2 — CPC and CTR

This is one of the strongest sequences. The comparison table establishes that CPC is constrained by product economics, the formula ladder makes maximum CPC calculable, and the decision flow prevents the learner from cutting a bid merely because one metric looks uncomfortable. The visual order is coherent and the lesson already contains independent calculation, worksheet work, quick check, and client language.[2]

The remaining issue is **answer timing**. The decision flow appears immediately before the independent calculation and `Your turn`, which is acceptable only if its branches require an actual selection. If it renders as a fully resolved flow, it becomes a pre-answer. Convert the flow into a first-pass choice: show the symptom and evidence, let the learner select the suspected lever, then reveal the rationale. Feedback should name the distinction between high CPC, low CTR, and low CVR rather than only restating the answer.

**Recommended score after revision: 11–12/12.**

### Lesson 2.1 — Match Types

The lesson’s three primitives express the right conceptual model: role comparison, hierarchy, and evidence-based routing. However, they are clustered together near the end of the explanatory content rather than distributed at the moment each concept is introduced.[3] This makes the learner see a complete system before working through a specific keyword, and the hierarchy can feel like an account diagram to memorize instead of a decision tool.

Use one concrete search term throughout the three visuals. First, ask whether the term is discovery, scaling, or protection. Then place that term into the hierarchy. Finally, show how the evidence changes the route over time. The learner should make the route decision before the hierarchy highlights the answer. The worksheet should capture the reason for the match type, not only the selected match type.

**Recommended score after revision: 11/12.**

### Lesson 2.3 — Negative Keywords

This is a strong operational lesson. The classification board, scope comparison, routing flow, and maintenance calendar form a credible progression from candidate term to safe action to recurring operating habit. It also aligns well with the weekly search-term report and worksheet handoff.[4]

The risk is **premature certainty**. The board currently presents classified examples with rationales, so the learner can read the answer without performing the classification. Add a first-pass mode with three unclassified candidates: one exact negative, one phrase negative, and one hold-for-evidence case. Reveal the rationale only after selection. Make one item intentionally ambiguous so the lesson teaches restraint, not just blocking. The maintenance calendar should also include a review threshold such as “recheck after enough spend or clicks,” without hard-coding a universal number.

**Recommended score after revision: 11–12/12.**

### Lesson 4.4 — Campaign Architecture in Practice

This is the best simulator-facing composition. The simulation rubric tells the learner what will be evaluated, and the decision flow gives an explicit build order: purpose, targets, bids, and budget. The sequence leads naturally into the campaign map, launch QA checklist, client language, and quick check.[5]

The only pedagogical risk is that the decision flow may reduce productive struggle if it is displayed as a finished answer before the learner builds. Treat the rubric as a pre-flight contract, but place the decision flow behind a “show coach sequence” reveal after the first attempt. Feedback should point to the exact rubric criterion that was missed. This preserves the simulator’s diagnostic value while keeping the learner supported.

**Recommended score after revision: 11–12/12.**

### Lesson 6.1 — Bid Strategies

The comparison table, effective-bid risk ladder, and strategy-routing flow form a sound progression from mechanism to exposure risk to strategy choice. The lesson’s taxi metaphors give the numbers a memorable mental model, while the worksheet and client-language sections support transfer beyond the lesson.[6]

The main issue is **strategy selection timing**. The full routing flow appears before the `What Would YOU Do?` section and can give away the choice. Present the scenario and ask the learner to choose fixed, up-and-down, or down-only first. Then reveal the risk ladder and decision rationale. Add one counterexample in which the apparently safer strategy is not the right answer because the objective or data maturity is different. That teaches conditional reasoning instead of strategy matching by slogan.

**Recommended score after revision: 11/12.**

### Lesson 7.1 — Search-Term Analysis

The five-category classification board, weekly decision flow, and operating-cycle timeline correctly model search-term triage as a repeatable operating system rather than a one-time cleanup task.[7] The lesson also contains a worksheet, client language, and quick check, which creates a good transfer path.

The gap is that the visual system is **framework-first rather than case-first**. Give the learner one actual search-term report row and force a category choice before displaying the five-category board as a reference. Then use the decision flow to route the chosen category to one action, and only after that show the weekly cadence. This ordering makes the cadence feel earned by the decision instead of appended as a calendar graphic. Add feedback for the cannibalizer and surprise categories, because those are the places where the learner needs judgment rather than a simple rule.

**Recommended score after revision: 11/12.**

### Lesson 8.3 — Competitor Benchmarking and Actionable Insights

The competitive gap matrix followed by the insight router is a strong evidence-to-action chain. The learner can see that a benchmark is not useful until it produces an opportunity, vulnerability, or bounded test with an owner and next check.[8]

The main risk is **subjective scoring**. Labels such as “Strong,” “Weak,” and “Not using” are useful for orientation but need observable criteria. Add a compact scoring key: what counts as evidence of presence, weakness, or absence, and what minimum evidence is required before escalating a gap into a campaign action. Convert one matrix row into a learner-selected opportunity and route it through the insight router before revealing the recommended action. This will keep the component from becoming a completed consultant dashboard.

**Recommended score after revision: 11/12.**

## Cross-lesson patterns

The dominant systemic weakness is **completed-answer density**. Six of the eight lessons show the framework, the example, and the recommended action before the learner is required to make a choice. The components should support two states: a learner state with one constrained decision and a coach state with the rationale revealed. This can be implemented without new dependencies by adding an optional `revealMode` or `initiallyCollapsed` contract to the existing visual primitives.

The second weakness is **visual clustering**. Lessons 2.1, 2.3, and 7.1 place multiple visuals in a block before the active attempt. A stronger instructional rhythm is: one concept visual, one learner action, one feedback visual, and then one operating artifact. This limits working-memory demands and gives every visual a job in the sequence.

The third weakness is **weak handoff metadata**. The visual components explain the reasoning, but the MDX does not consistently state which worksheet field, simulator action, or review log the learner must complete next. Add an optional `handoff` field to the directive schema with `artifact`, `action`, and `successSignal`. This would make the lesson contract inspectable and prevent visually polished but operationally incomplete lessons.

## Revision priority

| Priority | Lessons | Revision |
| --- | --- | --- |
| P0 | 1.1, 2.1, 7.1 | Reduce redundant or clustered visuals; add one concrete learner case and hide the answer until selection. |
| P1 | 2.3, 6.1, 8.3 | Add deliberate uncertainty, observable evidence criteria, and reveal-after-choice behavior. |
| P2 | 1.2, 4.4 | Preserve the strong sequence while tightening feedback and simulator challenge protection. |

## Conclusion

The deep lessons are not decorative. They already encode meaningful PPC reasoning, evidence, trade-offs, and operating habits. The next quality jump is not more graphics; it is **better timing of information**. The learner should encounter the signal, make a bounded choice, see the evidence-based rationale, and then record or execute the decision. That pattern should become the acceptance test for every future visual lesson.
