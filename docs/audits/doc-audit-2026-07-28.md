## Summary

Found and fixed significant doc drift in three files. `docs/build-spec.md`, `docs/business-layer.md`, and `docs/admin-backend.md` all had stale entity names, wrong paths, and outdated terminology that no longer matched the codebase.

## Changes Made

### 1. `docs/build-spec.md`

**What was wrong:**

- Layer 1 (domain) entity list still named `Payment`, `Refund` instead of `Order`
- Layer 2 (ports) used `PaymentGateway` instead of `IPaymentGateway`; wrong paths like `gateways/`
- Layer 3 (usecases) had `StartCheckout`, `AdminIssueRefund`, `HandlePaymentWebhook` as separate; used `PaymentRepository`
- Layer 4 (infra) had `PayMongoGateway`, `PaymentRepository`, wrong file paths
- Layer 5 (app) listed `src/middleware.ts` instead of `src/proxy.ts`; webhook route as `/api/paymongo/webhook` instead of `/api/webhooks/paymongo`
- Step 6 of "Adding a feature" recipe referenced `src/app/actions/<name>/index.ts` (nested, doesn't exist)
- Container example used `Container` type with non-existent properties
- Sprint count said 13 instead of 16

**What was done:**
Python script (`fix_build_spec.py`) patched all four remaining sections: app layer file shape, composition container type block, step 6 path, and sprint count. (Earlier edits had already fixed the layer-by-layer file trees.)

### 2. `docs/business-layer.md`

**What was wrong:**

- Enrollment flow step 5: webhook path was `/api/paymongo/webhook` instead of `/api/webhooks/paymongo`
- Enrollment flow step 6b-c: referenced `PaymentRepository` and `Checkout` — neither exists; idempotency is via `PrismaWebhookEventLog`
- Enrollment flow step 6d: created `Payment` row and `Receipt` row — neither table exists
- State machine text: `Payment.status` instead of `Order.status`
- Refund window: "default 7 days" everywhere — actual value is 30 days (`REFUND_WINDOW_DAYS = 30` in `src/domain/values/OrderRefund.ts`)
- Refund flow: `PaymentRepository`, `Payment.status`, separate `Refund` row — all wrong
- `AccessPolicy` interface: `canRequestRefund(user, payment: Payment)` — `Payment` doesn't exist
- Discount codes section: `StartCheckout` use case (doesn't exist), `Checkout` row (doesn't exist), `Payment.amount` (wrong)
- `DiscountCodeUse` table mentioned — doesn't exist; single-use tracked via order history
- State machines section: `Payment` heading, separate `Refund` state machine — neither matches reality
- What Lives Where: wrong paths, wrong port names, `HandlePaymentWebhook` listed for PDF rendering

**What was done:**
Full file rewrite. Replaced all `Payment`/`Receipt`/`Refund`/`Checkout` references with `Order`. Fixed refund window to 30 days. Updated webhook path. Added notes that receipt PDF and `BusinessProfile` are not yet implemented. Updated the "What Lives Where" table with correct port names and use case names.

**What was wrong:**

- Layout tree: `payments/[id]/override-refund/page.tsx` — doesn't exist; refund override is inline on the payments detail page
- Layout tree: `refunds/[id]/page.tsx` — actually `refunds/[orderId]/page.tsx`

- Layout tree: missing `settings/2fa-setup/page.tsx`
- Layout tree: `users/[id]/impersonate/route.ts` — should be `.action.ts`
- All `Payment`/`Refund` references should be `Order`
- Dashboard tiles: `Payment.amountMinor`, `Refund.count` — wrong entity names
- `pendingRefunds` from `Refund.count({ status = PENDING })` — `Refund` table doesn't exist; tracked differently
- `PaymentRepository` in Payments section
- Wrong use case name `AdminIssueRefund` — actual use case is `ProcessRefund`
